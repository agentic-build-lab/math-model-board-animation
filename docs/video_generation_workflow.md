# 视频生成工作流

## 设计原则

质量优先于自动化。结构化输入只负责表达内容意图，最终构图、节奏、字体、色彩和留白必须由模板规则与人工 review 共同控制。

## 标准流程

### 1. 选题定义

明确视频要解释的模型、目标受众和核心结论。

输出：

- 模型名称。
- 一句话解释。
- 公式或结构。
- 观众需要带走的直觉。
- 是否需要真实数据。

### 2. 脚本切片

把内容拆成若干 scene。每个 scene 只解决一个认知动作：

- 提出问题。
- 展示公式。
- 解释变量。
- 画出曲线。
- 标出关键区域。
- 连接现实含义。

原则：一个 scene 不同时承担太多信息。

### 3. 输入配置

使用 JSON/YAML 描述标题、公式、解释、图表类型、动画方式、时长、强调点和字幕。配置文件不直接控制每个像素位置，只表达“要讲什么”和“要强调什么”。

### 4. 视觉模板选择

根据内容选择模板：

- 快速模型闪讲：黑板公式风。
- AI、系统、复杂网络：现代科技风。
- 课程推导、考试讲解：教学推导风。
- 论文、报告、研究解读：论文解读风。

### 5. 数据和图形生成

图形数据来源分三类：

- `synthetic`：用于概念解释的模拟曲线。
- `csv`：行情、实验、回测或业务数据。
- `computed`：从公式或模型参数计算得到。

所有数据进入统一图表接口，由模板决定颜色、坐标轴、线宽、透明度和动画节奏。

### 6. 时间轴编排

先做音频/字幕时间轴，再绑定视觉事件：

- 标题出现。
- 坐标轴出现。
- 公式出现。
- 曲线生长。
- 散点渐入。
- 重点框选。
- 标签出现。
- 结论强调。

没有音频时，先使用默认节奏；有旁白后再微调。

### 7. 渲染

初始路线沿用旧项目验证过的 PIL + numpy + ffmpeg：

- Python 逐帧生成画面。
- numpy 生成曲线、散点和模拟数据。
- PIL 绘制文字、公式、坐标轴和图形。
- ffmpeg 合成视频和音频。
- 自动生成 contact sheet。

后续可补充 LaTeX/MathText 公式渲染和 SVG 图形，但不在第一阶段强行引入复杂依赖。

### 8. 审片

每条视频至少检查：

- 公式是否正确。
- 字体是否清晰。
- 曲线是否可读。
- 高亮区域是否准确。
- 底部字幕是否遮挡主体。
- 背景颗粒是否过强。
- 颜色是否过饱和。
- 节奏是否拖沓。

### 9. 输出归档

每次渲染输出：

- 最终视频。
- contact sheet。
- 输入配置快照。
- 使用的脚本版本。
- 关键帧抽图。
- 审片备注。

## 质量红线

- 公式不能糊。
- 坐标轴不能抢主体。
- 大面积填充透明度必须克制。
- 画面宁可空，不要满。
- 强调色只能用于强调，不能把整屏染色。
- 自动布局不合适时必须人工修正。

## 阶段规划

### 阶段 0：风格实验

目标：确认高质量样片的视觉边界。

当前旧项目材料已经完成这一阶段的一部分，尤其是量化模型闪讲风格。

### 阶段 1：内部生产工具

目标：把复刻脚本拆成可配置的 renderer。

最小可用能力：

- 读取 JSON 输入。
- 支持 4 个模板。
- 支持 8-10 种基础图表。
- 生成视频和 contact sheet。
- 支持人工 review 后二次调参。

### 阶段 2：内容生产流水线

目标：支持连续生产一个栏目。

需要补齐：

- 选题库。
- 公式校对流程。
- 脚本模板。
- 配音/字幕对齐。
- 发布规格。

### 阶段 3：Codex skill

目标：把稳定工作流封装成 `math-model-board-animation`，让 Codex 遇到模型动画任务时自动调用。

### 阶段 4：产品化验证

目标：面向非工程用户验证输入、预览、调参和导出流程。
